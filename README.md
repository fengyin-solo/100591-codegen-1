# 光伏电站运行维护管理平台

面向电站台账、组串阵列、逆变器、汇流箱、跟踪支架、组件清洗、告警处置与发电结算的一体化光伏电站运行维护工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `pv-plant-ops:entries` 这一项，或调用 `resetModule(模块)`。

## 工作票流转约定

工作票不走通用动作通道（`local-service.runAction` 对 `ticket` 模块直接挡回），
全部规则收口在 `frontend/src/api/ticket-service.ts`：

- **顺序流转**：状态只能按 `已签发 → 已许可 → 已终结` 往下走。没许可的票不许出现终结记录，
  跳环改状态一律挡回，返回消息写清卡在哪一环；已终结的票只做归档，回不到许可环节。
- **电站联动**：许可与终结都要求所属电站处于「停运检修」状态，电站那边没就位就不放行；
  许可/终结记录会挂到电站台账的「停运检修记录」上。
- **票号唯一与幂等**：票号在同一电站内唯一，同一张票重复提交两次签发只生效一次，
  第二次按幂等处理不再建票。
- **整票退回**：票号、所属电站缺失或安全措施栏留白的，整票退回重填，不落库。
- **待办台账口径**：终结结论落到电站停运检修的「待办台账」，电站侧这两栏不是独立数据，
  而是按工作票实时重算的派生视图（`reconcileAllStationLedgers`），电站页与工作票页
  展示前都会对账，两块读到的处置口径必然一致。
- **时间冲突裁决**：两处时间打架时**以工作票上的记录为准**。理由：许可/终结时间是操作
  发生当时写在票上的原始凭证，电站台账只是由各票汇总出的投影；投影与凭证不一致时应当
  按凭证重算投影，而不是反过来改凭证。对账入口：工作票页「对账：按票重算电站台账」。
